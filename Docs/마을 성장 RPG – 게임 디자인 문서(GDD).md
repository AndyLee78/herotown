# 마을 성장 RPG – 게임 디자인 문서(GDD)

Nov 22, 2026 · @Lee Juyoung · v0.5

## 1. 개요

플레이어는 작은 마을의 영주가 되어, 마을을 찾아오는 모험가를 영웅으로 고용하고 던전에서 얻은 보상으로 마을을 키운다. 영웅은 나이를 먹고, 결혼하고, 자식을 남긴다. 마을은 세대를 거쳐 이어지는 영웅 가문의 터전이 된다.

| 항목 | 내용 |
| --- | --- |
| 가제 | 미정 (예: 영웅의 마을) |
| 장르 | 마을 경영 + 파티 RPG + 방치형 자동 탐험 |
| 세계관 | 정통 판타지 |
| 그래픽 | 귀여운 복셀(블록) 3D, 쿼터뷰 시점. 그래픽은 모두 코드로 만든다. 주요 장면(결혼·탄생, 보스 등장, 은퇴)은 카메라 클로즈업으로 연출 (11.7) |
| 플레이 형태 | 싱글 플레이. 엔딩 없이 계속되는 게임 |
| 수익 모델 | 무료 + 보상형 광고 (유료 재화 없음, 10.1) |
| 플랫폼 | 자체 웹사이트로 첫 공개 → 태블릿 → 모바일 → PC |
| 개발 | 1인 개발, Claude Code 사용, 기한 없음 |
| 레퍼런스 | 다키스트 던전(파티·스트레스), 풋볼 매니저(에이징·스카우팅), 카이로소프트 게임(마을 성장), 림월드(인물 관계), 유니콘 오버로드(전열·후열 편성과 조건부 작전) |

**핵심 재미 4가지**

1. **성장의 손맛**: 빈 터에 건물이 하나씩 생기며 마을이 커진다.
2. **사람 수집과 육성**: 찾아온 방랑자 중 숨은 원석을 알아보고 키운다.
3. **공략의 재미**: 후반 던전은 조합·장비·전략으로 풀어야 한다.
4. **세대의 이야기**: 전성기 영웅이 은퇴하고 그 자식이 뒤를 잇는다.

## 2. 핵심 게임 루프

한 바퀴는 고용 → 준비 → 탐험 → 보상 → 마을 성장이고, 성장한 마을이 다음 바퀴의 고용을 더 좋게 만든다. 이 루프 위에 에이징·결혼·출산이라는 느린 세대 루프가 겹쳐 돈다.

| 시간 단위 | 플레이어가 하는 일 |
| --- | --- |
| 한 번 접속 (5–15분) | 부재 중 보고서 확인, 건물 예약, 고용, 새 던전 도전 |
| 며칠 | 새 건물 해금, 상위 티어 던전 공략, 전직 |
| 몇 주\~몇 달 | 에이스 은퇴, 2세 육성, 가문 형성 |

## 3. 마을 시스템

마을은 \*\*마을 레벨(명성)\*\*이 오를 때마다 새 건물이 해금되고, 각 건물은 자원을 들여 레벨업한다. 마을 레벨은 던전 클리어, 건물 레벨 합계, 주민 수로 오른다.

### 3.1 마을 레벨 효과

- 방문자 수와 등급 상한 증가 (명성이 높을수록 좋은 영웅이 찾아옴)
- 건물 최대 레벨 상한 증가
- 건설 가능한 터(부지) 확장

### 3.2 건물 목록과 해금 순서 (초안)

| 해금 마을 Lv | 건물 | 역할 | 레벨업 효과 예시 |
| --- | --- | --- | --- |
| 1 | 마을 회관 | 마을 레벨, 건설 관리 | 다른 건물 최대 Lv 상한 |
| 1 | 여관(방문자 숙소) | 찾아온 방랑자가 머무는 곳, 고용 창구 | 방문자 수·체류 기간 증가 |
| 1 | 집 | 고용한 영웅의 거주지 | 수용 인원, 휴식 회복량, 부부 거주 가능 |
| 2 | 길드 | 퀘스트·의뢰 수주, 파티 편성 | 동시 출정 파티 수, 의뢰 등급 |
| 2 | 대장간 | 무기·방어구 제작·강화 | 제작 등급, 강화 성공률 |
| 3 | 신전 | 부상 치료, 사망 영웅 부활 | 치료 속도, 부활 비용 감소 |
| 4 | 연금술 공방 | 물약·소모품 제조 | 제조 종류, 동시 제조 수 |
| 5 | 훈련소 | 영웅 능력치·스킬 개발 | 훈련 효율, 동시 훈련 인원 |
| 6 | 마법 공방 | 장신구 제작, 마법 부여 | 장신구 등급, 옵션 슬롯 |
| 7 | 시장(제안) | 재료 거래, 상인 방문 | 판매가, 희귀 물품 등장 |
| 8 | 학교(제안) | 어린 2세 교육, 잠재력 발굴 | 성장기 성장률 보너스 |
| 9 | 선술집/광장(제안) | 영웅 간 호감도·교류 | 호감도 상승 속도 |
| 10 | 명예의 전당(제안) | 은퇴 영웅 기록, 가문 보너스 | 후손 능력 보정 |

"(제안)"은 요청에 없던 건물로, 결혼·자녀·에이징 시스템을 받쳐주기 위한 후보다. 빼도 된다.

### 3.3 건물 규칙

- 건물은 자원 + 건설 시간이 든다. 동시 건설 슬롯은 초반 1개.
- 일부 건물은 \*\*담당 주민(NPC 장인 또는 은퇴 영웅)\*\*을 배치할 수 있고, 담당자 능력이 결과물에 영향을 준다. 은퇴한 영웅에게 두 번째 삶을 주는 장치다.

### 3.4 마을 인구 상한 (제안)

영웅 수는 집(침상 수)으로 제한하고, 마을 레벨이 집을 얼마나 지을 수 있는지를 정한다. 5인 파티 기준으로 계산했다.

| 마을 단계 | 출전 가능 영웅 | 총 주민(아이·은퇴자 포함) | 근거 |
| --- | --- | --- | --- |
| 초반 (Lv 1–3) | 6–12 | 15 | 파티 1–2개 + 휴식 교대 인원 |
| 중반 (Lv 4–7) | 15–25 | 40 | 파티 3–4개, 첫 세대교체 시작 |
| 후반 (Lv 8+) | 최대 40 | 최대 80 | 동시 자동 파티 최대 6개(30명) + 로테이션 10명 |

- 40명을 넘기면 플레이어가 이름과 성격을 기억하기 어렵다. 더 늘리기보다 “누구를 남길지” 고민하게 만드는 것이 목표다.
- 상한에 다다르면 출생을 막지 않고 “집이 부족하다” 알림만 띄운다. 은퇴·해고로 자리를 만드는 것이 세대교체의 원동력이 된다.
- 마을 맵에 돌아다니는 주민 수는 기기 성능에 따라 자동으로 정한다 (11.6).

## 4. 영웅 시스템

영웅은 마을에 찾아오는 방문자 중에서 고용하며, 고용 전에는 일부 정보만 보인다. 풋볼 매니저의 스카우팅처럼 “숨은 잠재력”을 알아보는 것이 핵심 재미다.

### 4.1 방문과 고용

1. 방문자는 주기적으로 여관에 도착하고, 정해진 기간 머물다 떠난다.
2. 도착 시 보이는 정보: 이름, 나이, 성별, 클래스, 현재 능력치(범위로 표시).
3. 여관·길드 레벨이 높거나 면담을 하면 특성과 잠재력 등급이 더 정확하게 보인다.
4. 고용 조건: 계약금(골드) + 집의 빈 자리. 일부 영웅은 마을 명성이나 특정 건물을 조건으로 요구한다.
5. 고용한 영웅은 주급(유지비)을 받는다. 영웅은 스스로 떠나지 않으며, 플레이어만 해고할 수 있다. 해고된 영웅은 마을을 떠난다. 기혼 영웅을 해고하면 집을 비워야 하므로 배우자와 자녀까지 가족 전체가 떠나며, 해고 전에 떠날 가족 목록을 보여주고 확인을 받는다.

### 4.2 능력치

| 구분 | 항목 | 설명 |
| --- | --- | --- |
| 신체 | 힘, 민첩, 체력 | 근접 피해, 회피·속도, HP·지구력. 에이징 영향 큼 |
| 정신 | 지능, 의지, 지혜 | 마법 피해, 상태이상 저항, 치유·판단력. 늦게까지 유지 |
| 숨은 값 | 잠재력(상한), 성장 속도, 부상 내성 | 고용 전 보이지 않거나 범위로만 표시 |
| 전투 경험 | 레벨, 숙련도 | 던전 활동으로 상승 |

기본 능력치는 “레벨”보다 **나이·훈련·잠재력**으로 변한다. 레벨은 스킬 포인트와 장비 착용 조건에만 쓴다.

### 4.3 클래스 (초안)

| 클래스 | 역할 | 주 능력치 |
| --- | --- | --- |
| 전사 | 탱커, 적 어그로 | 힘, 체력 |
| 도적 | 딜러, 함정 해제, 보물 발견 | 민첩 |
| 궁수 | 원거리 딜러 | 민첩, 지혜 |
| 마법사 | 광역 딜러, 속성 공격 | 지능 |
| 성직자 | 힐러, 언데드 대응 | 지혜, 의지 |
| 음유시인 | 버프, 파티 사기 | 의지 |
| 무희 (여성 전용) | 서포터. 파티 회피·속도 버프, 적 현혹·디버프 | 민첩, 의지 |

클래스는 일정 조건(레벨, 훈련소 레벨)에서 **상위 직업**으로 전직한다. 예: 전사 → 성기사 / 광전사.

### 4.4 특성과 성격

- **특성(Trait)**: 전투·생활에 영향. 예: 강인함(부상 회복 빠름), 겸쟁이(도망 확률), 보물 사냥꾼, 야행성.
- **성격(Personality)**: 관계·만족도에 영향. 예: 사교적, 외톨이, 야망가, 온화함. 결혼 상대 선호와 파티 궁합을 정한다.
- 특성은 일부 자녀에게 유전된다 (6장).

### 4.5 영웅의 상태

건강 → 피로 → 부상 → 중상 → 사망. 피로는 집에서 쉬면 회복되고, 부상·중상은 신전에서 치료한다.

**사망 규칙 (확정)**

- 처음 사망하면 신전에서 부활할 수 있다(비용·대기 시간 있음). 부활한 영웅에게는 “죽음을 본 자” 표시가 붙는다.
- 두 번째로 사망하면 되살릴 수 없다. 영웅은 묘지에 묻히고 가계도에 기록된다.
- 사망하면(처음이든 영구 사망이든) 착용 장비마다 일정 확률로 던전에 잃어버린다(초깃값: 장비당 25%). 파티원이 살아 돌아오면 확률을 낮춘다(예: 10%). 영구 사망 후 남은 장비는 창고로 돌아와 유품으로 물려줄 수 있다.
- 자동 출정에서는 죽지 않는다(8.2). 그래서 두 번째 죽음은 항상 플레이어가 직접 보낸 출정에서만 일어난다.
- “죽음을 본 자”를 위험한 던전에 보낼 때는 출정 전 경고를 띄운다.

## 5. 에이징 커브

신체 능력치는 20대 후반에 정점을 찍고 30대 중반부터 줄고, 정신 능력치는 늦게까지 오른다. 그래서 나이에 따라 잘 맞는 클래스와 역할이 바뀐다. 아래 수치는 밸런싱 전 초깃값이다.

### 5.1 게임 내 시간

- 1년 = 4계절. 영웅은 생일에 한 살씩 먹는다.
- 가안으로 시작하고 플레이테스트 후 조정한다: 1계절 = 현실 약 1일(게임 내 1년 = 4일). 이 경우 한 영웅의 활동기(18\~45세)가 현실 약 3.5개월이 된다.

### 5.2 나이대별 변화 (초깃값)

| 나이 | 단계 | 신체 능력치 | 정신 능력치 | 비고 |
| --- | --- | --- | --- | --- |
| 0–13 | 유년 | 성장만 함 | 성장만 함 | 출전 불가, 학교·훈련소 교육 |
| 14–17 | 견습 | 빠르게 상승 | 상승 | 초급 던전만, 성장률 최고 |
| 18–24 | 성장기 | 상승 | 상승 | 훈련 효율 높음 |
| 25–31 | 전성기 | 정점 | 상승 | 전사·도적의 황금기 |
| 32–39 | 성숙기 | 서서히 하락 | 정점 | 마법사·성직자의 황금기 |
| 40–49 | 노련기 | 하락 | 유지 | 부상 회복 느려짐 |
| 50세\~ | 은퇴기 | 크게 하락 | 서서히 하락 | 은퇴 권유, 건물 담당·교관으로 전환 |
| 60–80 | 노년 | - | - | 자연사 확률 발생 |

### 5.3 개인차

- 영웅마다 **정점 나이**와 **하락 속도**를 갖는다(예: 조기 개화형, 대기만성형). 풋볼 매니저의 “설령 잠재력”처럼 숨겨진 값이다.
- 특성이 커브를 바꾼다. 예: “강건함”은 신체 하락을 5세 늦춘다.
- 훈련소는 하락을 늦출 수는 있지만 막을 수는 없다. 세대교체가 필연이 되도록 한다.
- 중상을 자주 입은 영웅은 하락이 일찍 온다.

## 6. 결혼·출산·2세

마을에 사는 영웅끼리 호감도가 쌓이면 연애·결혼으로 이어지고, 부부는 자녀를 낳는다. 자녀는 부모의 능력치·특성을 일부 물려받아, 마을이 직접 키운 영웅이 된다.

### 6.1 호감도와 관계 단계

| 단계 | 조건 (초안) | 효과 |
| --- | --- | --- |
| 낯선 사이 | 기본 | - |
| 동료 | 같은 파티 출정 누적 | 파티 시너지 소폭 |
| 친구 | 호감도 40+ | 파티 시너지 증가 |
| 연인 | 호감도 70+, 성격 궁합, 성인 | 같은 파티일 때 사기 상승 |
| 부부 | 연인 상태 + 플레이어 승인 + 빈 집 | 같은 집 거주, 출산 가능 |
| 역관계(제안) | 연인을 두고 경쟁, 다툼 | 같은 파티 배치 시 패널티 |

- 호감도는 같은 파티 출정, 선술집 등 교류 건물, 생명 구해주기 같은 전투 이벤트로 오른다.
- 결혼은 이성 간에만 가능하다. 자동으로 일어나지 않고, 두 영웅이 “청혼” 이벤트를 올리면 플레이어가 승인한다. 방치 중에는 대기 상태로 보관.

### 6.2 출산과 성장

1. 부부는 일정 확률로 임신 이벤트가 생긴다. 임신 중인 영웅은 일정 기간 출정 불가 또는 제한.
2. 아이는 0세로 태어나 에이징 표(5.2)대로 자란다. 14세부터 견습 출전.
3. 유년기에 학교·훈련소에 보내면 클래스 성향과 초기 능력치를 바꿀 수 있다.
4. 부부당 최대 자녀 수와 출산 가능 나이(예: 둘 다 45세 이하)를 둔다.

### 6.3 유전 규칙 (초안)

- **잠재력**: 부모 잠재력의 평균 ± 랜덤 편차. 아주 낮은 확률로 “천재”(부모보다 크게 높음)가 나온다.
- **능력치 성향**: 각 능력치의 성장 비중을 부모 중 한쪽 또는 혼합으로 물려받는다.
- **특성**: 부모의 특성 각각 약 30% 확률로 유전, 낮은 확률로 돌연변이 특성.
- **외형**: 머리 모양·눈·눈썹 같은 얼굴 부위는 부모 중 한쪽에서, 머리색·피부색·눈색은 부모의 색을 섞어 물려받아 누구의 자식인지 보이게 한다. 부위와 색 처리 방식은 11.7을 따른다.
- **가문**: 성(姓)과 가계도를 기록한다. 명예의 전당에 오른 조상이 있으면 가문 보너스.

### 6.4 성별 비율 관리

결혼이 가능하려면 마을 안 성별이 한쪽으로 너무 치우치면 안 된다. 다음 방식으로 균형을 맞춘다.

- 자녀 성별: 기본 50:50.
- 방문자 성별: 마을 거주 영웅의 성비가 60:40을 넘으면, 부족한 성별의 방문 확률을 높인다(예: 50% → 65%).
- 무희(여성 전용)를 제외한 클래스는 성별과 무관하게 가능하다. 능력치에도 성별 차이는 없다.
- UI에 “마을 인구 현황”(나이대·성별·미혼/기혼)을 보여줘 플레이어가 고용으로 균형을 잡을 수 있게 한다.

### 6.5 재혼

배우자가 영구 사망하면 애도 기간(초깃값: 1계절)이 지난 뒤 다시 연애·결혼할 수 있다. 출산 가능 나이 제한(6.2)은 그대로 적용되고, 이전 배우자의 자녀는 같은 집에서 함께 산다.

### 6.6 감정과 사기

영웅마다 \*\*사기(0–100)\*\*가 있고, 마을과 가족의 사건에 감정으로 반응한다. 사기는 전투 능력과 훈련 효율에 영향을 주며(예: 사기 80 이상 +5%, 30 이하 −10%), 성격에 따라 반응 크기가 다르다.

| 감정 | 계기 (예시) | 효과 (초깃값) |
| --- | --- | --- |
| 슬픔 | 배우자·부모·자녀·친한 동료의 영구 사망 | 사기 크게 하락, 1계절 동안 서서히 회복. 애도 중 자동 출정 제외 옵션 |
| 기쁨 | 결혼, 출산, 자녀의 첫 출전·전직, 가족의 던전 최초 클리어 | 사기 상승, 일정 기간 훈련 효율 보너스 |
| 자부심 | 보스 처치, 마을 레벨업 | 사기 소폭 상승 |
| 불안 | 파티 연속 패배, 가족이 중상 | 사기 하락, 겁쟁이는 더 크게 |
| 서운함 | 같은 파티에서 혼자만 자주 빠짐, 연인을 빼앗김(역관계) | 사기 하락, 호감도 변화 |

**축제**

- 플레이어가 골드·재료를 써서 열면 마을 전체 사기가 오르고, 축제 기간에는 호감도 상승이 빨라져 연애·결혼 이벤트가 자주 일어난다.
- 계절마다 한 번 열 수 있다. 예: 봄 파종제, 여름 무술 대회, 가을 수확제, 겨울 추모제(떠난 영웅을 기리며 슬픔을 빨리 덜어줌).
- 주요 축제는 마을 광장의 카메라 클로즈업 장면으로 보여준다(11.7). 주최 건물은 광장·선술집(3.2)이 맡는다.

## 7. 던전과 전투

던전은 티어가 올라갈수록 “스펙으로 밀기”에서 “공략으로 풀기”로 바뀐다. 티어마다 새 공략 요소를 하나씩 가르치는 구조다.

### 7.1 던전 구조

- 던전 = 여러 층(방) + 마지막 보스. 층마다 전투, 함정, 보물, 휴식 지점 중 하나.
- 파티는 최대 5명. 기본형은 탱 1, 딜러 2, 서포트 1, 힐러 1이지만 필수는 아니며, 기본형을 벗어난 조합이 특정 던전에서 더 유리하게 설계한다. 전열 2 + 후열 3의 위치 개념.
- 던전을 나오면 피로가 쌓이고 부상이 남는다. 연속 출정을 막고 로테이션을 만든다.

### 7.2 티어별 공략 요소

| 티어 | 대표 던전 (가칭) | 필요한 것 | 새로 등장하는 공략 요소 |
| --- | --- | --- | --- |
| 1 | 마을 뒷산 동굴 | 능력치 합 | 없음. 두들겨 패기 |
| 2 | 버려진 광산 | 역할 분담 | 탱·딜러·힐러 구성이 없으면 크게 불리 |
| 3 | 언데드 묘지 | 속성 | 물리 저항 적, 성직자·화염 무기 유리 |
| 4 | 독늪 습지 | 상태이상 대비 | 독·마비, 해독 물약·저항 장신구 필요 |
| 5 | 도적 요새 | 함정·기습 | 도적 없으면 함정 피해, 후열 기습 대비 |
| 6 | 마량 성채 | 보스 패턴 | 페이즈 전환, 특정 턴에 광역기, 차단·해제 필요 |
| 7+ | 용의 둥지 등 | 종합 | 던전 어픽스(변수) 매번 다름, 사전 정찰 필요 |

### 7.3 전투 방식 (확정)

- **자동 전투 + 작전 설정**: 플레이어는 전투 중 조작하지 않고, 출정 전에 편성·위치·장비·작전(예: “힐러 보호 우선”, “HP 30% 미만 물약”)을 정한다.
- 방치형과 잘 맞고 모바일 조작이 가벼다. 대신 깊이는 “출정 전 준비”에서 나온다.
- 전투는 턴제가 아닌 틱(행동 게이지) 방식으로 자동 진행되며, 3D 전투 화면에 전열·후열 캐릭터를 세우고, 전투 로그와 캐릭터 동작(11.7)으로 보여준다.
- 출정 전 작전은 세 가지다. 타겟 우선순위(체력 낮은 적 / 후열 / 보스), 회복을 시작할 체력 %, 후퇴할 평균 체력 %. 후퇴는 패배다.
- 근접은 전열이 살아있는 동안 후열을 때리지 못한다. 힐러는 기준 아래인 아군을 회복하고, 서포터는 한 번 버프하거나 디버프한다.
- 층 사이에는 체력이 일부만 돌아온다. 티어 2 보스는 강한 단일 공격과 지속 피해를 쓴다.
- 패배 후 **전투 리포트**가 원인을 한 줄로 알려준다. 티어 2에서는 탱커 없음, 힐러 없음 순으로 먼저 말한다. 예: “탱커가 없어 후열이 무너졌다.”

### 7.4 정찰과 정보

상위 던전은 처음에 적 구성이 “?”로 가려져 있다. 정찰(도적 단독 출정)이나 길드 정보 구매로 약점·패턴을 미리 알 수 있다.

### 7.5 보상

골드, 재료(건물·제작용), 장비 드롭, 명성, 경험치. 최초 클리어 보상은 크게, 반복 클리어는 작게 주어 새 던전 도전을 유도한다.

### 7.6 프로토타입 판정 (2026-11-20)

같은 시드의 성인 영웅 1,000회로 확인했다. 수치는 `npm run simulate`로 다시 뽑는다.

| 편성 | 뒷산 동굴 | 버려진 광산 |
| --- | --- | --- |
| 기본형 (탱·딜·궁·음유·힐) | 100% | 100% |
| 딜러 5 | 100% | 0% |
| 힐러 없음 | 100% | 0% |
| 탱 없음 | 100% | 0% |
| 서포터 2 | 100% | 100% |

판단 기준(동굴 70% 이상, 광산 기본형 60% 이상, 탱 없음·힐러 없음 20% 이하)은 모두 넘었다. 같은 기본형에서 회복 기준만 80%와 0%로 바꾸면 광산 승률이 100%에서 0%로 바뀐다. 탱커 없이 광산에 들어가면 리포트가 “탱커가 없어 후열이 무너졌다”로 다음 편성을 알려 준다.

단계 1로 넘어가도 된다. 건물, 에이징·결혼, 제작, 광고, 오프라인 진행은 그때 다룬다. 마을 화면은 이 판정과 별도로 이미 프로토타입에 있다.

## 8. 자동화(방치) 시스템

처음 도전하는 던전은 플레이어가 직접 편성하고 보내며, 한 번 클리어한 던전은 영웅들이 스스로 반복 출정한다. 플레이어의 시간은 “새 던전 공략”과 “마을 결정”에 쓰이고, 반복 노동은 자동화가 맡는다.

### 8.1 자동 탐험 규칙

- 클리어한 던전만 자동 출정 대상이 된다.
- 영웅은 자기 능력·피로·성격에 따라 던전을 고르고 스스로 파티를 짠다. 야망가는 어려운 곳, 겸쟁이는 쉬운 곳을 고른다.
- 플레이어는 **운영 정책**으로 방향만 정한다. 예: “철광석 우선 수집”, “부상자는 출정 금지”, “고정 파티 유지”.
- 자동 출정은 효율이 직접 플레이보다 낮다(예: 보상 80%). 운영 정책을 잘 짜면 효율이 오른다.
- 매우 쉽게 반복하는 던전은 “소탕” 처리(전투 연출 없이 결과만).

### 8.2 오프라인 진행

- 접속하지 않은 동안에도 시간이 흐른고, 다음 접속 때 한꺼번에 계산한다(최대 누적 시간 예: 12시간).
- 접속 시 “부재 중 보고서”: 획득 자원, 부상·사망, 나이 상승, 출생, 방문자, 대기 중인 결정(청혼 승인 등).
- 자동·오프라인 출정에서는 사망하지 않는다. 최악은 중상이며, 사망은 플레이어가 직접 보낸 출정에서만 일어난다(영구 사망 규칙 때문). 방치했더니 에이스가 죽어있는 경험은 이탈로 이어진다.

### 8.3 자동화 확장

길드 레벨에 따라 동시 자동 파티 수가 늘고, 대장간·연금술의 자동 제작 대기열도 열린다. 후반에는 마을 운영 자체가 대부분 자동이 되고, 플레이어는 고난도 던전과 세대 관리에 집중한다.

## 9. 장비·아이템·제작

장비는 던전 드롭보다 **마을에서 만드는 것**이 주력이다. 던전은 재료를, 마을은 완성품을 주는 구조로 루프를 묶는다.

### 9.1 장비 슬롯

무기 1, 방어구 1, 장신구 2, 소모품(물약) 2 (초안).

### 9.2 제작 건물별 산출물

| 건물 | 만드는 것 | 공략 역할 |
| --- | --- | --- |
| 대장간 | 무기, 방어구, 강화 | 기본 공격·방어, 속성 무기(화염·은 등) |
| 연금술 공방 | 회복·해독·버프 물약, 폭탄 | 상태이상 대응, 긴 던전 지구력 |
| 마법 공방 | 반지·목걸이, 마법 부여 | 저항, 특수 효과, 빌드 완성 |

### 9.3 장비 등급과 옵션

- 등급: 일반 → 고급 → 희귀 → 영웅 → 전설.
- 상위 등급은 랜덤 옵션을 갖는다. 옵션이 던전 기믹(독, 언데드 등)에 맞물리게 해서 “이 던전용 세트”를 만드는 재미를 준다.
- 장비 내구도·수리는 없다. 한 번 만든 장비는 닳지 않는다.
- 유품 계승(제안): 은퇴·사망한 영웅의 장비를 자녀가 물려받으면 작은 보너스.

## 10. 경제와 자원

자원은 네 가지 층으로 나눠 쓰임새가 겹치지 않게 한다.

| 자원 | 얻는 곳 | 쓰는 곳 |
| --- | --- | --- |
| 골드 | 던전, 의뢰, 시장 판매 | 고용비, 주급, 치료·부활, 건설 |
| 기초 재료 (목재·석재·철) | 초중반 던전, 마을 생산(제안) | 건물 건설·레벨업 |
| 특수 재료 (약초·마석·몸스터 부산물) | 티어별 던전 고유 드롭 | 장비·물약·장신구 제작 |
| 명성 | 던전 최초 클리어, 의뢰 | 마을 레벨업, 고급 방문자 유치 |

- **골드 소모원**이 충분해야 인플레이션이 없다. 영웅 주급이 가장 큰 고정 지출이고, 영웅을 막 모으는 것을 억제한다.
- 특수 재료를 티어별 던전에 묶어 두면 클리어한 던전을 자동 반복할 이유가 생긴다.
- 유료 재화는 없다. 수익은 보상형 광고로 낸다 (10.1).

### 10.1 광고 보상 (수익 모델)

광고는 모두 플레이어가 직접 눌러서 보는 보상형이고, 광고는 “시간과 편의”를 줄 뿐 게임 규칙을 깨지 않는다. 광고를 한 번도 보지 않아도 모든 콘텐츠를 할 수 있어야 한다.

**원칙**

1. 강제 전면 광고(화면 전환 시 자동 재생)는 넣지 않는다.
2. 광고로도 두 번째 사망은 되돌릴 수 없다. 영구 사망의 무게감을 지킨다.
3. 항목마다 하루 횟수 제한을 두고, 버튼에 남은 횟수를 표시한다.
4. 랜덤 보상을 주는 경우 확률을 공개한다(광고 플랫폼 정책 요구사항).

**광고 보상 항목 (초안)**

| 위치 | 광고 보상 | 하루 제한 | 비고 |
| --- | --- | --- | --- |
| 신전 | 첫 부활 비용 면제 또는 부활 대기 즉시 완료 | 사망 1건당 1회 | 두 번째 사망에는 표시하지 않음 |

## 11. 플랫폼·UI·기술 스택

하나의 웹 코드베이스로 시작해, 같은 코드를 포장만 바꿔 태블릿·폰·PC로 내보내는 것을 원칙으로 한다. 이 게임은 메뉴·표·상태창이 대부분이라 웹 UI 기술과 잘 맞는다.

### 11.1 플랫폼 확장 순서

| 단계 | 플랫폼 | 방식 (제안) | UI 고려 |
| --- | --- | --- | --- |
| 1 | 웹 (데스크톱 브라우저) | 자체 웹사이트(정적 호스팅 + PWA)로 첫 공개 | 마우스, 넓은 화면 |
| 2 | 태블릿 | PWA 또는 Capacitor로 앱 포장 | 터치, 가로 화면 |
| 3 | 폰 | Capacitor로 iOS/Android 앱 | 세로 화면, 한 손 조작, 하단 탭 |
| 4 | PC (Steam 등) | Tauri 또는 Electron으로 데스크톱 앱 | 단축키, 창 크기 |

처음부터 **터치에서도 되는 UI**(호버에 의존하지 않기, 터치 영역 44px 이상)로 만들면 2–3단계 비용이 크게 줄어든다.

### 11.2 기술 스택 (제안)

- **언어**: TypeScript.
- **UI**: React(또는 Svelte) — 메뉴·표·영웅 상세창.
- **마을 맵·전투 연출**: three.js(WebGL) — 3D 렌더링이 필요한 부분만. 메뉴·표는 React로 둔다.
- **저장**: 브라우저 로컬 저장(IndexedDB) + 세이브 파일 내보내기 (11.5). 기기 간 연동이 필요해지면 클라우드 세이브(예: Supabase, Firebase) 추가.
- **시뮬레이션 코어 분리**: 전투·에이징·유전·오프라인 계산을 화면과 분리된 순수 TS 모듈로 만든다. 테스트가 쉽고, 나중에 서버 검증으로 옮기기도 쉽다.
- **시드 기반 난수**: 같은 시드면 같은 결과가 나오게 해서 버그 재현과 오프라인 계산을 안정시킨다.
- **데이터 주도**: 클래스·건물·던전·아이템·에이징 표를 JSON(또는 스프레드시트 → JSON)으로 두고 코드는 읽기만 한다. 밸런스 조정을 코드 수정 없이 할 수 있다.

**광고 연동 (제안)**: 웹은 Google AdSense의 H5 Games Ads(Ad Placement API)로 보상형 광고를 넣고, 앱으로 포장할 때는 AdMob을 쓴다. H5 Games Ads는 신청 후 승인을 받아야 쓸 수 있으므로, 광고 호출부를 인터페이스로 감싸 두고 승인 전에는 “가짜 광고”(바로 보상 지급)로 개발·테스트한다. [출처: Google AdSense 도움말](https://support.google.com/adsense/answer/9959170), [Ad Placement API 가입 안내](https://developers.google.com/ad-placement/docs/signup)

### 11.3 Claude Code로 개발할 때

- 이 GDD를 저장소에 Markdown으로 두고, 시스템별로 파일을 나눈다(예: `Docs/village.md`, `Docs/dungeons.md`). AI가 필요한 부분만 참조하기 쉽다.
- 저장소 루트의 `CLAUDE.md`에 명령어, 코딩 규칙, “시뮬레이션 코어는 UI를 import하지 않는다” 같은 원칙을 적어둔다.
- 기능을 작게 자르고(예: “방문자 생성기”), 각 단위마다 테스트를 같이 만들게 한다. 에이징·유전 같은 확률 시스템은 “100년 시뮬레이션” 테스트로 밸런스를 확인한다.
- 시간 가속(디버그 모드)을 초기에 만든다. 세대교체를 몇 분 만에 확인할 수 있어야 한다.

### 11.4 다국어 구조

기본 언어는 영어이고 한국어를 함께 제공하며, 언어를 추가할 때 코드를 고치지 않고 번역 파일만 더하면 되게 만든다.

1. 화면 문구를 코드에 직접 쓰지 않고 키로 부른다. 예: `t('hero.hired', { name })`.
2. 언어별 파일을 둔다: `locales/en.json`, `locales/ko.json`. 새 언어 = 파일 하나 추가.
3. 첫 실행 때 기기 언어(`navigator.language`)가 `ko`로 시작하면 한국어, 그 외에는 영어를 고른다. 설정에서 바꾸면 그 선택을 저장해 우선한다.
4. 복수형·변수가 들어가는 문장은 ICU 형식을 지원하는 라이브러리(예: i18next)로 처리한다. 숫자·날짜는 브라우저 `Intl` API로 표시한다.
5. 한국어 조사(이/가, 은/는, 을/를)는 영웅 이름 끝글자 받침에 따라 고르는 도우미 함수를 둔다. 이름이 계속 생성되는 게임이라 필수다.
6. 아이템·건물·특성 이름 같은 게임 데이터도 키로 두고 번역 파일에서 읽는다. 영웅 이름은 언어 공통의 판타지 이름 풀을 쓴다.
7. 그림 안에 글자를 넣지 않는다. UI는 글자가 30% 길어져도 깨지지 않게 여유를 둔다.
8. 폰트는 언어별로 바꿀 수 있게 한다. 한글을 지원하고 둥근 복셀 화면과 어울리는 폰트를 고른다(라이선스 확인 필요).

### 11.5 세이브

- **웹**: IndexedDB에 자동 저장하고, 설정에 “세이브 파일 내보내기/가져오기”를 둔다. 브라우저 데이터를 지우면 세이브가 사라진다는 안내와 주기적인 백업 알림을 넣는다.
- **모바일 앱**: 앱 내부 저장소에 저장하고, 내보내기는 OS 공유 기능으로 파일을 클라우드 드라이브 등에 저장하게 한다. 세이브 파일을 OS 자동 백업 대상에 포함한다. 기기 변경은 플랫폼별 클라우드 세이브를 쓴다: Android는 Google Play Games의 저장된 게임, iOS는 iCloud. 웹↔앱 또는 Android↔iOS 이동은 세이브 파일 내보내기/가져오기로 한다.
- **공통**: 세이브에 버전 번호를 넣어, 게임이 업데이트돼도 이전 세이브를 변환해 읽게 한다. 파일에는 손상 검사용 체크섬을 넣는다.

### 11.6 성능과 표시 인원 자동 조절

돌아다니는 주민 수는 프레임 상태를 보고 자동으로 정할 수 있다. 게임 계산(능력치·나이·관계)은 모든 주민에 대해 항상 하고, 화면에 그리는 수만 조절한다.

1. 최근 2초간 평균 프레임 시간을 잰다. 목표는 60fps(프레임당 16.7ms), 저전력 모드에서는 30fps.
2. 목표보다 느리면 표시 인원을 2명 줄이고, 3초 이상 여유가 있으면 2명 늘린다(급하게 오르내리지 않게 간격을 둠).
3. 표시 인원은 최소 8명, 최대는 마을 주민 전체.
4. 화면에 없는 주민은 “건물 안에 있음”으로 표현하고 건물 위에 인원 수를 표시한다. 화면 밖 캐릭터는 그리지 않는다.
5. 설정에 “자동 / 낮음 / 높음”을 둔다.

### 11.7 아트 방향과 제작 (복셀 3D)

그래픽은 **귀여운 복셀(블록) 3D**다. 쿼터뷰 고정 시점(정사영 카메라), 상자를 조합한 SD 캐릭터와 건물, 밝은 파스텔 색감, 부드러운 그림자. 그래픽은 모두 코드로 만들고 외부 이미지나 AI 이미지 생성은 쓰지 않는다. 시안: `prototypes/voxel3d/index.html` (2026-11-22).

이 방향을 고른 이유:

- 코드로 찍은 픽셀 아트는 품질이 나오지 않았고, 회화풍 2D는 이미지 생성 도구와 손 작업이 필요했다. 복셀 3D는 형태와 조명만 정하면 렌더러가 화면을 그려 주므로, 1인 개발과 AI 코딩만으로 계속 만들 수 있다.
- 유전(6.3)과 에이징(5.2)이 그림 작업 없이 숫자 조정으로 끝난다.
- 마을, 전투, 상세창이 하나의 그림체로 통일된다.

**화면별 표현**

| 화면 | 표현 |
| --- | --- |
| 마을 | 쿼터뷰. 타일 지형 위에 건물·나무·소품, 주민이 돌아다닌다. 드래그로 이동, 확대·축소 |
| 전투 | 전열 2 + 후열 3을 마주 세우고 캐릭터를 카메라 쪽으로 살짝 돌린 3/4 시점. 근접 돌진, 화살·마법 발사체, 피해 숫자, 체력 바, 쓰러짐 |
| 영웅 상세창·여관 | 해당 영웅을 확대한 3D 미리보기 |
| 건물 | 레벨이 오르면 크기·지붕 단수·장식이 바뀐다 |
| 던전 | 티어마다 바닥·벽 색과 소품(횃불, 수정, 뼈 등)으로 분위기를 바꾼다 |
| 주요 장면 | 결혼·탄생·보스 등장·은퇴·축제는 카메라 클로즈업과 포즈, 이름표로 연출한다. 일러스트는 넣지 않는다 |

**캐릭터 구성**

| 요소 | 방식 |
| --- | --- |
| 몸 | 다리·몸통·팔·머리 상자. 관절은 상자 회전으로 움직인다 |
| 클래스 의상 | 클래스마다 색과 장식(어깨 보호대, 로브, 치마, 모자, 화살통) |
| 무기 | 클래스별 1종(검, 단검, 활, 지팡이, 철퇴, 류트, 부채). 등급 차이는 색·빛으로 |
| 머리 모양 | 짧은 머리, 삐죽 머리, 묶은 머리, 긴 머리, 단발, 민머리. 필요할 때 추가 |
| 색 | 머리색은 연속 색값이라 부모 색을 섞을 수 있다. 피부 5단계, 눈 4색 |
| 나이 | 10세→성인으로 키가 크고 머리 비율이 줄어든다. 25세부터 수염(유전), 38세부터 흰머리, 55세부터 굽은 자세 |

- 방어구·장신구는 외형에 반영하지 않는다(무기만 보인다).
- 동작: 대기(숨쉬기), 걷기, 공격(근접·마법·활), 회복, 피격, 쓰러짐. 필요할 때 늘린다.
- 모자를 쓰는 클래스(마법사, 음유시인)는 머리 모양이 가려진다. 상세창에서는 모자를 벗긴 모습도 볼 수 있게 한다.
- 단계 1에서는 외형(피부·머리색·눈·머리 모양·수염·키)을 영웅 id에서 정해 늘 같게 보이게 한다. 단계 2에서 유전 값으로 바꾼다.

**성능 기준**

- 시안 측정(데스크톱 GPU): 주민 12명일 때 그리기 호출 약 550회, 80명일 때 약 2,300회. 폰에는 무겁다.
- 게임 적용 후 측정(2026-11-22): 부위별로 합친 결과 캐릭터 10명이 있는 마을에서 프레임당 약 78회. 캐릭터당 약 6회라 80명이면 약 560회로 예상한다.
- 본 구현에서는 캐릭터의 상자를 부위(다리·몸통·팔·머리)별로 하나의 형태로 합쳐 색은 정점 색으로 넣는다. 캐릭터당 그리기 호출을 6회 안팎으로 줄이고, 정적인 지형·건물·나무는 통째로 합친다. 목표: 주민 80명이 있는 마을에서 그리기 호출 600회 이하.
- 그림자는 기기 성능에 따라 해상도를 낮추거나 끈다. 11.6의 표시 인원 자동 조절은 그대로 적용한다.
- 화면 계산(애니메이션)은 게임 계산과 분리한다. 시뮬레이션 코어는 3D 코드를 모른다(11.2).

## 12. MVP 범위와 로드맵

처음 만들 MVP는 “고용 → 던전 → 보상 → 건물” 루프 하나가 재밌는지만 확인하는 데 집중한다. 결혼·자녀는 루프가 재밌다는 게 확인된 뒤 붙인다. 1인 개발에 기한이 없으므로 날짜 대신 “다음 단계로 넘어가는 기준”으로 진행한다. 광고는 단계 1 공개 시점부터 넣는다. 단계 1 공개 전에 기존 픽셀 화면을 복셀 3D(11.7)로 바꾼다.

| 단계 | 목표 | 포함 범위 | 다음 단계로 넘어가는 기준 |
| --- | --- | --- | --- |
| 0. 프로토타입 | 전투·성장 계산이 돈다 | 텍스트 UI, 영웅 생성, 자동 전투 1종, 던전 2개 | 전투 결과가 편성에 따라 달라짐 |
| 1. MVP | 핵심 루프가 재밌다 | 회관·여관·집·길드·대장간·신전, 클래스 4개, 던전 티어 1–3, 자동 반복, 오프라인 보고서, 로컬 저장, 첫 접속 길잡이 의뢰(7단계), 자체 웹사이트 공개 | 테스터가 자발적으로 다시 접속 |
| 2. 세대 | 사람 이야기가 생긴다 | 에이징 커브, 은퇴, 호감도·결혼·출산·유전, 훈련소 | 플레이어가 특정 영웅·가문에 애착 |
| 3. 공략 깊이 | 후반이 어렵고 재밌다 | 연금술·마법 공방, 티어 4–7, 보스 패턴, 정찰, 전투 리포트 | 상위 던전 클리어에 편성 고민이 필요 |
| 4. 확장 | 더 많은 기기에서 | 클라우드 세이브, 태블릿 → 폰 → PC 출시 | 기기별 UI 테스트 통과 |

프로토타입은 그래픽 없이 텍스트·표로만 만드는 것을 권한다. 이 장르의 재미는 숫자와 결정에서 나오므로 그래픽 없이도 검증할 수 있다.
