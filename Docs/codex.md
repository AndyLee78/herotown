# 도감·업적과 알림 (2026-11-27)

다른 방치형·경영형 RPG와 비교해서 보강한다. 엔딩이 없는 게임이라 스스로 세울 중장기 목표(도감·업적)와, 다시 들어올 이유(알림)가 필요하다.

## 도감

마을이 한 번이라도 만난 것·얻은 것을 영구히 기록한다. 영웅이 죽거나 장비를 팔아도 지워지지 않는다.

| 칸 | 기록하는 때 | 채울 수 있는 수 |
| --- | --- | --- |
| 몬스터 | 원정 보고서에 나온 적(정예는 따로 표시) | `monsters.json`의 몬스터 수 |
| 던전 | 처음 클리어(`cleared`) | 일반 던전 + 특수 던전 |
| 고유 장비 | 창고·영웅 장비에 처음 들어온 고유 장비 | 12 |
| 세트 | 한 영웅이 세트 3개를 처음 함께 낀 때 | 4 |
| 천부 | 고용·출생으로 마을에 천부를 가진 영웅이 처음 들어온 때 | 14 |
| 직업 | 그 직업 영웅을 처음 고용한 때 | 7 |

- 저장: `GameState.codex = { monsters: string[], elites: string[], uniques: string[], sets: string[], gifts: string[], classes: string[] }`. 던전은 `cleared`를 그대로 쓴다.
- 기록은 상태가 바뀌는 곳(원정 정산, 드롭·교환, 고용·출생, 장착)에서 한다. 같은 id는 한 번만.
- 세이브 버전을 올린다. 예전 세이브는 지금 상태(로스터·창고·장비·`cleared`·`history`)에서 채울 수 있는 만큼 채워서 시작한다.

## 업적

도감과 마을 기록에서 판정하는 목표. 달성하면 보상을 **받기** 버튼으로 받는다(자동 지급 아님, 받는 맛). 데이터는 `src/data/codex.json`.

| 묶음 | 예 | 보상 예 |
| --- | --- | --- |
| 도감 | 몬스터 10·25·전부, 고유 장비 3·6·12, 세트 1·4, 천부 5·10·14, 직업 7 | 골드, 용맹 훈장 |
| 원정 | 첫 클리어 1·5·전부, 레이드 처치 1·10, 심연 10·20·40층 | 용맹 훈장, 정수 |
| 마을 | 마을 레벨 5·10, 영웅 10·20명, 건물 전부 Lv3 | 골드, 명성 |
| 가문 | 첫 결혼, 첫 아이, 3대 가문, 명예의 전당 1·5 | 사기, 골드 |

- 저장: `GameState.achievements: string[]`(받은 업적 id). 달성 여부는 매번 판정하고, 받은 것만 저장한다.
- 행동: `{ type: 'claimAchievement', id }`(달성 전 `locked`, 이미 받음 `missing`).
- 보상은 초반을 크게 흔들지 않게 작게 잡는다(5d 측정의 30일 골드·훈장 획득량의 5% 안팎). 숫자는 작업에서 정하고 문서에 남긴다.

## 알림

지금 게임은 서버가 없는 정적 사이트(GitHub Pages)다. 그래서 단계를 나눈다.

1. **지금(웹):** 설정에서 "알림 받기"를 켜면 브라우저 알림 권한을 묻는다. 게임이 열려 있거나(다른 탭·최소화·설치한 PWA가 백그라운드에 있음) 하는 동안, 원정 귀환·건설 완료·대장간 완료·방문자 도착·레이드 새 주 시각에 서비스 워커로 알림을 띄운다. 알림을 누르면 게임이 앞으로 나온다. 같은 일로 두 번 알리지 않는다. 기본은 꺼짐.
2. **앱 출시 때:** 앱의 로컬 알림(예약 알림)으로 같은 시각들을 예약한다. 앱을 완전히 닫아도 온다.
3. **완전히 닫힌 웹에서 오는 푸시**는 푸시 서버가 필요해서 지금은 하지 않는다(서비스를 고르는 결정이 필요).

- 알림 시각 계산은 core 순수 함수(`upcomingEvents(state): { kind, at, refId }[]`)로 둔다. 2단계 앱 알림도 같은 함수를 쓴다.
- 알림 문구 ko/en. 개인정보는 넣지 않는다(영웅 이름 정도만).
