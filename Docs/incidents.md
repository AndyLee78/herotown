# 선택이 있는 마을 사건 (2026-11-28)

지금 마을에서는 일이 자동으로만 일어난다. 가끔 짧은 사건이 생기고 플레이어가 고른 답에 따라 사기·관계·보상이 달라지게 해서, 영웅들의 삶에 끼어드는 순간을 만든다. 이름은 **사건(incident)**이다. 계절 행사(`events.ts`, 행사 던전)와 헷갈리지 않게 한다.

## 규칙

- **생기는 때:** 게임 시간으로 계절마다 1–2번(현실 약 12–24시간에 한 번). 시각은 세이브 시드와 사건 순번으로 정해진다(같은 세이브는 같은 결과). 비운 동안에도 생기지만 **한 번에 하나만** 기다린다. 기다리는 사건이 있으면 새 사건은 생기지 않는다.
- **기다리는 시간:** 생긴 뒤 게임 시간 1계절 안에 답하지 않으면 "그냥 지나갔다"(선택지마다 정해 둔 `ignore` 결과, 보통 아무 일 없음이나 작은 손해).
- **공통 발생 조건:** 고용한 성인 영웅이 최소 2명 있어야 한다(원정 중인 영웅 포함). 비와 작은 잔치 제안은 원정 중이 아닌 성인 영웅이 최소 2명 있어야 한다. 후보가 없으면 다음 확인 시각만 미룬다.
- **조건:** 사건마다 조건이 있다(예: 성격이 맞부딪히는 두 영웅, 마을에 아이, 선술집 Lv1 이상, 골드 50 이상). 조건에 맞는 사건 중에서 가중치로 고른다. 최근 5개 안에 나온 사건은 다시 나오지 않는다.
- **등장 인물:** 사건이 고른 영웅 id를 저장한다(`actors`). 답할 때 그 영웅이 없거나(죽음·은퇴·원정 중이 아닌 해고) 조건이 깨졌으면 선택지 대신 "상황이 바뀌었다"로 닫힌다. 원정 중인 영웅은 등장시키지 않는다.
- **결과는 정해져 있다.** 선택지마다 결과 목록이 있다. 확률이 있는 결과(예: 60% 성공)는 시드로 굴리고, 화면에는 확률을 "성공할 것 같다/어렵다" 정도로만 보인다.

## 결과의 종류

core가 이미 가진 것만 쓴다.

| 종류 | 설명 |
| --- | --- |
| `gold`, `materials`, `vault` | 골드·재료·금고(훈장 등) ± |
| `fame` | 명성 + |
| `morale` | 등장 영웅 한 명·둘 모두·마을 전체의 사기 ±(`feel`로, 감정 종류 joy/grief 등) |
| `affinity` | 두 등장 영웅 사이 호감도 ±(`bonds`) |
| `fatigue` | 등장 영웅 피로 ± |
| `xp` | 등장 영웅 경험치 + |
| `visitor` | 방문자 하나를 바로 데려옴(조건: 여관 자리) |
| `gear` | 낮은 등급 장비 하나(`rollDrop`, 마을 레벨에 맞는 티어) |
| `nothing` | 아무 일 없음(문구만) |

큰 손해(영웅 부상·죽음·장비 잃음)는 넣지 않는다. 방치형이라 모르는 사이에 큰 손해가 나면 안 된다.

| `bard` | 떠돌이 시인이 마을 노래를 지어 준다 | 명성 20 이상 | 사례한다(골드 −25, 명성 +5) / 거절(없음) |
| `wolf` | 밤에 늑대가 마을 가축을 노린다 | 없음 | 탱커를 세운다(탱커 피로 +10, 명성 +2) / 덫을 놓는다(나무 −10, 60%로 뼈 +12, 아니면 없음) |
| `confession` | 한 영웅이 다른 영웅을 좋아하게 됐다고 털어놓는다 | 친구 사이(호감 friendAt 이상), 둘 다 미혼 이성 | 응원한다(호감 +15) / 지켜본다(호감 +5) |
| `grieving` | 동료를 잃은 영웅이 잠을 못 이룬다 | 최근 1년 안에 사망자, 그와 친했던 영웅 | 곁에 있어 준다(그 영웅 사기 +15, 피로 +5) / 일로 잊게 한다(경험치 +16, 사기 −5) |
| `festivalIdea` | 영웅들이 작은 잔치를 열자고 한다 | 마을에 성인 영웅 2명 이상, 이번 계절 축제 안 열림 | 연다(골드 −40, 마을 사기 +10) / 다음에(사기 −3) |
| `ancientCoin` | 아이가 오래된 동전을 주워 왔다 | 아이 1명 이상 | 마을 금고에(골드 +30) / 아이에게 준다(아이 사기 +15) |

골드 선택지 비용은 10–40이다. 초반 고용비 한 번 안팎이며, 가장 비싼 거래는 골드가 60 이상일 때만 제안한다. 마을 전체 사기 효과는 +5–10으로 축제와 비슷한 규모다. 한 영웅이나 한 가족에 집중되는 효과는 +15까지 적용한다. 표에 별도로 적지 않은 사건은 만료 시 수치 변화가 없다.

## 저장

세이브 버전을 하나 올린다.

- `GameState.incident: { id, actors: string[], at, expiresAt } | null`(기다리는 사건).
- `GameState.incidentNonce: number`, `nextIncidentAt: number`, `recentIncidents: string[]`(최근 5개).
- `GameState.incidentLog: { id, choice, at }[]`(최근 20개, 확률 분기와 실제 바뀐 수치도 기록).
- 행동 `{ type: 'resolveIncident', choice }`. 없는 사건·없는 선택지는 `missing`, 선택지의 조건(골드 부족, 선술집 없음)이 안 맞으면 `poor`/`locked`.
- 예전 세이브는 `incident: null`, 다음 사건 시각은 불러온 시각 + 계절의 절반.

- 조건에 맞는 사건이 없으면 계절의 1/4 뒤 다시 확인한다. 사건이 대기 중이면 만료 시각을 확인하고, 사건이 닫힌 시각부터 다음 간격을 센다.
- 재접속 보고에는 대기 사건 ID와 비운 동안 만료된 사건 ID를 기록한다. 최근 사망 확인에 필요한 사망 시각과 친구 ID는 묘지에 남긴다.

## 화면

- 사건이 기다리고 있으면 마을 화면에 말풍선 배지("마을에 일이 생겼다"). 누르면 사건 창: 그림 대신 등장 영웅 얼굴, 짧은 글(두세 문장), 선택지 2–3개(비용과 대략의 결과 한 줄). 고르면 결과 글과 바뀐 수치.
- 재접속 보고에 "비운 동안 생긴 일"(기다리는 사건이 있으면 한 줄, 그냥 지나간 사건도 한 줄).
- 알림(`upcomingEvents`)에 사건 생김을 더한다.
- 사건 글은 ko/en. 영웅 이름·성별·성격을 넣어 문장을 만든다(i18next 보간). 같은 사건도 성격에 따라 대사 한 줄이 달라지면 좋다(선택).
